# Lesson 12 — GROUP BY 分组聚合

> 第 11 课我们学了"对整张表求和、求平均"。这节课我们学**把表分成若干组**，再分别求和、求平均 —— 这是绝大多数业务报表的真正形状。

## 我们要学什么

只要业务上出现"按 XX 分组看 XX"这种说法 —— **按品类看销售额**、**按出纳员看营业额**、**按月份看趋势** —— 背后几乎都是一个 `GROUP BY`。

这节课我们围绕这几个点练手：

| 构件 | 一句话 |
|------|--------|
| `GROUP BY col` | 把所有 `col` 相同的行收进同一组 |
| `GROUP BY` + `COUNT/SUM/AVG` | 每组返回一行聚合结果 |
| `GROUP BY col1, col2` | 多列组合分组（比如月份 + 品类） |
| `ORDER BY <聚合>` | 按聚合结果排序（榜单的标准写法） |
| "必须出现在 GROUP BY 里或被聚合" | 最经典的 GROUP BY 报错 / 陷阱 |

学完之后，你能直接做出一堆便利店店长每天都会看的小报表。

## 数据库故事

数据是一家**便利店**一个月的销售流水。

| 表名 | 内容 | 行数 |
|------|------|------|
| `sales` | 每一笔小票（商品、品类、日期、数量、金额、出纳员） | 120 |

字段说明：

- `category`：商品大类 —— `drinks` / `snacks` / `tobacco` / `household` / `lottery`
- `sale_date`：销售日期，ISO 字符串，覆盖 2025-05 整个月
- `cashier`：当班的出纳员（4 个人轮班）
- `total_amount`：这一笔的金额（已含税，美元）

## 关于 SQL 注释

每个 example 文件开头都有大段 `--` 注释。SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长说明的时候很方便。
 */
```

数据库会**直接忽略**注释，所以注释怎么写都不影响查询结果。我们在每个 example 文件里把"业务问题"和"为什么这么写"写在 SQL 旁边，就是希望你以后回头看一眼注释就能立刻想起这条 SQL 在干嘛。
