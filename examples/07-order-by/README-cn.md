# Lesson 07 — 用 ORDER BY 给结果排序

> 同样一份数据，排序方式不同，讲出来的故事就完全不同。这一节我们把 `ORDER BY` 玩透。

## 我们要学什么

之前几节课我们都在"过滤"——`WHERE` 帮我们挑出感兴趣的行。
但拿回来的行**顺序**是数据库自己定的，不一定是你想要的。

这节课我们学的就是**主动控制结果顺序**：

| 构件 | 一句话 |
|------|--------|
| `ORDER BY col` | 按某一列升序排（默认 ASC） |
| `ORDER BY col DESC` | 按某一列降序排（最大的在前） |
| `ORDER BY a, b` | 先按 a 排，a 相同再按 b 排 |
| 混合 `ASC` / `DESC` | 每一列单独指定方向 |
| `NULLS LAST` | 把 NULL 值塞到结果末尾 |
| `ORDER BY 1` | 用列号代替列名（能用，但脆） |

学会这一节，你就能回答"最好的 10 部是哪些"、"按年份和时长一起排"、"先按类型分组再按评分排"这一大类问题。

## 数据库故事

这节课的数据是一个小型的**流媒体平台片库**——电影 + 剧集混在一张表里。

| 表名 | 内容 | 行数 |
|------|------|------|
| `titles` | 一行一部作品（片名、类型、上映年份、单集/单片时长、IMDb 评分、烂番茄评分、累计观看小时数） | 40 |

故意只用一张表，让你把注意力放在 `ORDER BY` 本身上。
注意：少数几部老片我们没有烂番茄评分（`rotten_score` 是 NULL），这是为了在 [example_05.sql](./example_05.sql) 里专门练习一下"排序时怎么处理 NULL"。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
