# Lesson 17 — 自连接（Self-Join）

> 一张表怎么和它"自己"连？当数据里藏着一棵树（比如员工 → 上级）时，自连接就是最自然的写法。

## 我们要学什么

这节课只学一个动作：**让同一张表在 FROM 里出现两次（甚至三次）**。

为什么需要这么做？因为有些关系本来就指向"自己人"——员工的经理也是员工，回复的父帖子也是帖子，零件由其它零件组成。这种"自引用外键"（self-referencing foreign key）在数据库里随处可见，自连接就是回答它的标准工具。

| 构件 | 一句话 |
|------|--------|
| `FROM t AS e JOIN t AS m ON e.fk = m.pk` | 让同一张表用不同别名扮演两个角色 |
| `LEFT JOIN` + `IS NULL` | 找到"链条顶端"（没有上级的人） |
| 自连接 + `GROUP BY` + `COUNT` | 数每个经理底下有多少直接下属 |
| 自连接两次 | 沿着层级往上跳两级（员工 → 经理 → 经理的经理） |
| 别名（alias）的真正威力 | 同一张表可以同时是"员工表"和"经理表" |

## 数据库故事

这节课模拟一家**连锁零售店的员工组织结构**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `staff` | 每个员工一行：员工 ID、姓名、岗位、所在门店、直属上级 ID（指回本表，顶层为 NULL） | 20 |

组织结构是 **3 层深**：

- **第 1 层**：2 位 **regional manager**（区域经理），他们的 `manager_id` 是 NULL——没有人管他们。
- **第 2 层**：5 位 **store manager**（店长），分布在 5 家门店，分别向某位区域经理汇报。
- **第 3 层**：13 位**一线员工**——assistant manager（副店长）/ floor lead（值班组长）/ cashier（收银员），每人向自己的店长汇报。

`manager_id` 列是一个**自引用外键**：它指回 `staff.employee_id`。所以"员工和经理"看似是两张表的关系，其实是同一张表的关系——这正是自连接登场的地方。

## 先自己探索一下

正式开始前，**强烈建议你先自己动手点一点**：

- 在 DBeaver 左侧栏里展开 `staff`，双击表名预览数据。
- 重点看 `manager_id` 这一列：它是数字，但这些数字其实是另一行的 `employee_id`——它指回**同一张表**。
- 试着用肉眼把链条捋一遍：找一个 cashier，沿着 `manager_id` 找到他的店长；再用店长的 `manager_id` 找到区域经理。
- 注意 `manager_id` 为空的两行，他们就是这棵"组织树"的根。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
