# Lesson 14 — INNER JOIN：把两张表拼起来问问题

> 一张表只能回答一半的问题。当"宠物的名字"在 A 表、"看病的原因"在 B 表，你需要 JOIN 把它们对上号。

## 我们要学什么

这节课的主角是 **`INNER JOIN`**——也是你在工作中用得最多的一种 JOIN。

我们会一步一步练以下技能：

| 构件 | 一句话 |
|------|--------|
| `INNER JOIN ... ON ...` | 用一个共同的键，把两张表"拼"成一张宽表 |
| 表别名 `p`、`v` | 给长长的表名起一个一两个字母的小名 |
| 列名限定 `p.name` / `v.vet_name` | 两张表都有 `name` 列时，必须告诉数据库你说的是哪一个 |
| `INNER JOIN` + `WHERE` | JOIN 完之后，WHERE 可以筛任意一侧的列 |
| 裸写 `JOIN` | `JOIN` = `INNER JOIN`，关键字可以省略 |

学会 INNER JOIN，你就跨过了"只会查单表"到"能跨表回答业务问题"的那道坎。
后面所有的 LEFT JOIN、多表 JOIN、自连接，都是在它之上的小变体。

## 数据库故事

练习数据是一个小型**宠物诊所**的日常台账。

| 表名 | 内容 | 行数 |
|------|------|------|
| `pets` | 每只在册宠物的基本信息（名字、品种、主人、出生日期等） | 20 |
| `visits` | 每一次到诊所就诊的记录（哪只宠物、什么时候、什么原因、哪位兽医、多少钱） | 40 |

两张表通过 `pet_id` 关联：
- `pets.pet_id` 是宠物的唯一编号。
- `visits.pet_id` 指向就诊的是哪只宠物（**外键**）。

平均下来每只宠物来过 2 次，但有的来了 3 次（比如 Charlie），有的只来了 1 次。
这是真实诊所里非常典型的"父表 + 子表"形状。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
