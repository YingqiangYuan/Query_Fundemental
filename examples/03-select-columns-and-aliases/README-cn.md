# Lesson 03 — 挑列、改名

> 上一节我们用 `SELECT *` 把整张表拿出来看。这一节学一件更日常的事：**只挑我们想要的列**，并且**给它换个好看的名字**。

## 我们要学什么

真实工作中很少 `SELECT *`。更多时候是"只要这几列"、"列名换一下让报表好看"。这节课练这几个最小动作：

| 构件 | 一句话 |
|------|--------|
| `SELECT col1, col2` | 只挑出想要的列（叫"投影 / projection"） |
| 调整列的顺序 | SELECT 列表的顺序就是结果的顺序 |
| `AS new_name` | 给列起别名，让结果列名更易读 |
| 省略 `AS` | 别名可以不写 `AS`，但推荐写 |
| 同一列出现两次 | 同一列可以列两次、起不同的别名 |

学会之后，你就能把一份杂乱的原始表，变成贴近业务、人话命名的结果——这是数据日常工作里最高频的一步。

## 数据库故事

这节课的练习数据是一家咖啡馆的**饮品菜单**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `drinks` | 每一杯饮品的信息（名字、品类、杯型、奶种、糖浆、热量、价格、是否季节限定） | 30 |

只有一张表——和 Lesson 02 一样，我们希望你这节课把注意力放在"选列"和"改名"上，不被多表关系分心。

## 先自己探索一下

正式开始前，**强烈建议你先自己动手点一点**：

- 在 DBeaver 左侧栏里展开 `drinks`，双击表名预览数据。
- 看每一列叫什么名字、是什么类型——尤其注意 `category`、`size`、`milk_type`、`syrup` 这几列的取值有哪些。
- 滚一滚那 30 行数据，对手里这份菜单有个大致印象：哪些是咖啡？哪些是茶？哪些是季节限定？

光看是看不会 SQL 的，但是看过一遍之后，下面的查询会更有"画面感"——你能预想到查询大概会返回什么，再去验证自己的预想，比"对着新数据猜结果"学得快得多。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——注释和代码住在一起，比单独翻教程要省事得多。
