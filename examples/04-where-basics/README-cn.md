# Lesson 04 — WHERE 基础

> 学会了 SELECT，能把整张表拿出来。但实际工作中，没人想看整张表——大家想看的是**符合条件的那一部分**。这节课就讲怎么"挑出我要的行"。

## 我们要学什么

这节课的主角是一个关键字：**`WHERE`**。

它的作用很简单：**把不符合条件的行过滤掉**，只留下你关心的那些。

我们会练这几个最基础的比较操作：

| 写法 | 一句话 |
|------|--------|
| `WHERE col = 'value'` | 等于（文本要用单引号） |
| `WHERE col != 'value'` 或 `<>` | 不等于 |
| `WHERE col > N` / `< N` | 严格大于 / 严格小于（不含边界） |
| `WHERE col >= N` / `<= N` | 大于等于 / 小于等于（含边界） |
| `WHERE col = NULL` | **会返回空结果**——本课最重要的"坑" |

最后那个 `= NULL` 不是教你怎么写，而是让你**亲眼看到它的失败**。
这是几乎每个初学者都会踩的坑，我们故意把它放进来让你踩一次——
真正的解法 `IS NULL` 在 Lesson 06 才正式登场。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
