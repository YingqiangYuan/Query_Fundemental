# Lesson 05 — 组合条件的 WHERE：AND / OR / NOT

> 真实世界的筛选条件，几乎从来不会只有一个。我们一起来学习怎么用 AND / OR / NOT 把多个条件拼起来。

## 我们要学什么

[examples/04-where-basics](../04-where-basics/) 里我们学过怎么写一个单条件的 `WHERE`，比如 `WHERE type = 'yoga'`。
但现实里客户的需求通常是这样：

> "我想要一间海景的豪华房（deluxe）、有阳台、住得下两个人，而且每晚不超过 300 块。"

一个条件根本不够用。这节课我们就把多个条件**组合**起来。

| 构件 | 一句话 |
|------|--------|
| `A AND B` | 两个条件**都**满足才留下 |
| `A OR B` | 两个条件**有一个**满足就留下 |
| `NOT A` | 把条件的真假**反过来** |
| `A AND (B OR C)` | 用**括号**控制 AND / OR 的先后顺序 |
| 三个以上条件 | 真实业务里经常一长串 AND |

这节课最大的一个"坑"是：当 AND 和 OR 同时出现时，**优先级**和你下意识读的顺序不一样。
我们专门用一个例子把它讲清楚。

## 数据库故事

这节课的练习数据是一个**酒店客房库存表**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `hotel_rooms` | 每间客房的属性（房型、朝向、床数、最大入住人数、是否有阳台、夜间价格、楼层） | 50 |

字段说明：

- `room_type`：`standard` / `deluxe` / `suite`
- `view`：`city`（城景）/ `ocean`（海景）/ `courtyard`（庭院景）
- `beds`：床的张数
- `max_occupancy`：最多可入住人数
- `has_balcony`：`1` 有阳台，`0` 没有
- `nightly_rate`：每晚价格（美元）
- `floor`：楼层

只有一张表，是故意的——这节课我们只想把"组合条件"练扎实，多表 JOIN 后面再讲。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
