# Lesson 02 — 最基础的 SELECT

> 不带 WHERE、不带 GROUP BY、不带 JOIN —— 只用最最基础的 SELECT，能问出哪些问题？

## 我们要学什么

这节课只有一个目标：**让你对 SELECT 完全脱敏**。

我们会练四个最常用的最小 SQL 构件：

| 构件 | 一句话 |
|------|--------|
| `SELECT *` | 把整张表拿出来看 |
| `LIMIT n` | 只取前 n 行（先看看数据长什么样） |
| `COUNT(*)` | 数一共多少行 |
| `DISTINCT col` | 看某一列有哪些不重复的值 |

这四个动作是你之后所有更复杂查询的"起手势"——
学会了，能直接回答一堆基础业务问题；
学不会，再多语法也拼不出来。

## 数据库故事

这节课的练习数据是一个非常小的**书店库存表**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `books` | 每一本书的基本信息（书名、作者、类型、年份、页数、定价、库存数量） | 20 |

只有一张表，是故意的。
我们希望你这节课专注在 SELECT 本身，不被多表关系分心。
后面的课程会逐步加表、加关系。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
