# Lesson 22 — 窗口函数：排名

> 不让 `GROUP BY` 把行压扁，又要在每一行上挂一个名次 —— 这就是窗口函数（window function）擅长的事。

## 我们要学什么

到目前为止，要算"排名"，你只能先 `ORDER BY` 然后用脑子数。
本节课我们引入 **窗口函数**，让数据库帮你把名次直接挂到每一行上：

| 构件 | 一句话 |
|------|--------|
| `ROW_NUMBER() OVER (ORDER BY ...)` | 给每一行打一个从 1 开始的、永不重复的编号 |
| `RANK()` | 同分并列；下一个名次会跳号（1, 2, 2, 4, ...） |
| `DENSE_RANK()` | 同分并列；下一个名次不跳号（1, 2, 2, 3, ...） |
| `PARTITION BY` | 按分组重置排名（每个组各自 1, 2, 3, ...） |
| "Top-N per group" 套路 | CTE 算出 `rn`，外层 `WHERE rn <= 3` |

记住一句话区分窗口函数和 `GROUP BY`：
**`GROUP BY` 会把多行压成一行；窗口函数保留每一行，只是新增一列**。

## 数据库故事

练习数据是一个**足球联赛的比赛结果表**。每场比赛拆成两行（一队一行），
方便我们排"哪支队伍打得最猛""每队最高分的三场比赛"这种问题。

| 表名 | 内容 | 行数 |
|------|------|------|
| `match_results` | 每队每场比赛的进球、失球、结果（W/D/L）、赛事类型（league/cup） | 80 |

数据里**故意安排了进球数相同的多场比赛**（例如有多场 5 球、9 场 4 球），
这样后面 `RANK()` 和 `DENSE_RANK()` 在同分时的差别才看得见。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛 ——
注释和代码住在一起，比单独翻教程要省事得多。
