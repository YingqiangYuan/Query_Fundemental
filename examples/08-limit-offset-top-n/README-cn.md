# Lesson 08 — LIMIT / OFFSET / Top-N

> 排好序之后，怎么"只取前 N 条"、"取第二页"、"翻到第三页"？这节课就讲这个。

## 我们要学什么

这节课围绕**结果集的裁切**展开——给定一堆已经排好序的行，如何只拿你真正想要的那一段。

| 构件 | 一句话 |
|------|--------|
| `ORDER BY ... DESC LIMIT N` | "Top-N" 经典套路——榜单前几名 |
| `LIMIT N OFFSET M` | 跳过前 M 条，再取 N 条——典型分页第二页起 |
| `LIMIT M, N`（SQLite 速记） | 等价写法，参数顺序容易记反 |
| 通用分页公式 | `LIMIT page_size OFFSET page_size * (page - 1)` |
| ⚠️ 没有 `ORDER BY` 的 `LIMIT` | 引擎"随便给你 N 条"——反面教材 |

**一句最重要的话**：**`LIMIT` 永远要和 `ORDER BY` 一起出现**。
单写 `LIMIT 5` 不等于"前 5 名"，只等于"扫到第 5 行就停"——
谁先被扫到完全看引擎心情。

这节课的数据是一份**播客每周排行榜**——和 Apple Podcasts、Spotify 网站上看到的那种榜单一样。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
