# Lesson 18 — WHERE 里的子查询

> 当你想问"这个值在不在另一张查询的结果里"，子查询就是答案。我们一起来看看 `IN`、`EXISTS`、以及它们各自的 NULL 陷阱。

## 我们要学什么

这节课的主题是 **WHERE 子句里的子查询**——把"另一条 SELECT 的结果"当成过滤条件来用。

我们会练五种最常用的写法：

| 写法 | 一句话 |
|------|--------|
| `WHERE col IN (SELECT ...)` | 当前行的 `col` 是否出现在子查询的结果里 |
| `WHERE col NOT IN (SELECT ...)` | 不在子查询结果里——**但碰到 NULL 会翻车** |
| `WHERE EXISTS (SELECT ...)` | 子查询是否至少返回一行（"存不存在") |
| `WHERE NOT EXISTS (SELECT ...)` | 子查询一行都返回不了（NULL-safe，是 `NOT IN` 的替代品） |
| `WHERE col > (SELECT AVG(...) ...)` | 用标量子查询的单个数值做比较 |

这一节最关键的一课是：**`NOT IN` 遇到 NULL 会静默返回 0 行**。
教科书里都会提，但只有自己亲眼看见过一次，以后写代码才会下意识地避坑。
所以这节课我们刻意把数据造得能复现这个 bug，让你亲手踩一脚。

## 数据库故事

这节课的数据是一个**迷你交友 App**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `users` | 每个用户的基本信息（用户名、年龄、城市、最后活跃时间）。**少数不活跃账号 `last_active_at` 是 NULL** | 30 |
| `matches` | 每一次配对（`user_a_id` 主动方、`user_b_id` 被动方、配对时间、聊天消息数）。**有几条 `user_b_id` 是 NULL**——表示一方发起、对方还没回应的"挂起邀请" | 54 |

为什么要故意留 NULL？因为这正是 `NOT IN` 陷阱的触发点——
没 NULL，你看不到 bug；看不到 bug，你以后就还会写错。

## 先自己探索一下

正式开始前，**强烈建议你先自己动手点一点**：

- 在 DBeaver 左侧栏里展开 `users` 和 `matches`，双击表名预览数据。
- 数一数：`users` 里 `last_active_at IS NULL` 的有几个？`matches` 里 `user_b_id IS NULL` 的有几条？
- 顺手挑一个用户，看看他/她在 `matches` 里作为 `user_a_id` 出现了几次、作为 `user_b_id` 出现了几次。

预先把这份数据"装进脑子"以后，下面的子查询会清晰很多——
你能预想到每一条查询大概应该返回谁，再去验证自己的预想。

## 跟着例子练

依次打开下面五个 SQL 文件，**一条一条**复制到你的 SQL 编辑器里执行：

- 每个文件最上面有一段注释，告诉你这条 SQL 想回答**什么业务问题**、为什么这么写。
- **先读注释**，预想一下结果。
- **运行**它，看真实结果。
- 看完结果再读一遍注释，对照一下是不是和你想的一样。

| 文件 | 学到什么 |
|------|----------|
| [example_01.sql](./example_01.sql) | `IN (SELECT ...)` —— 用子查询当作"白名单"过滤 |
| [example_02.sql](./example_02.sql) | `NOT IN (SELECT ...)` —— **会触发 NULL 陷阱，返回 0 行** |
| [example_03.sql](./example_03.sql) | `EXISTS (SELECT ...)` —— 相关子查询，问"有没有" |
| [example_04.sql](./example_04.sql) | `NOT EXISTS (SELECT ...)` —— `NOT IN` 的 NULL-safe 替代品，修好 example_02 |
| [example_05.sql](./example_05.sql) | `col > (SELECT AVG(...) ...)` —— 标量子查询当作比较的右值 |

**重点流程**：跑完 `example_02.sql` 看见 0 行别慌——那正是预期效果。然后立刻跑 `example_04.sql`，看到 4 个真正的"墙花用户"被找出来。这就是这节课最重要的一刻：你**亲眼**看见了 `NOT IN` 和 `NOT EXISTS` 在有 NULL 的世界里行为不同。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
