## 我们要学什么

这节课只有一个核心：**搞清楚 `WHERE` 和 `HAVING` 的区别**。

很多刚学 SQL 的人会卡在这两个关键字上 —— 它们看起来都在"过滤"，但过滤的对象不一样：

| 关键字 | 过滤的是 | 在什么时候过滤 |
|--------|----------|----------------|
| `WHERE` | **原始的每一行** | **GROUP BY 之前** |
| `HAVING` | **分组之后的整组数据** | **GROUP BY 之后** |

我们会练这几个动作：

- `GROUP BY user_name HAVING AVG(steps) >= 8000` —— 最常见的 HAVING 用法
- 把 WHERE 写法和 HAVING 写法**放在一起对比**，看清楚它们回答的是不同的问题
- 一条完整的 SELECT 语句：`WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`
- `HAVING` 里写多个条件（`AND` / `OR`）

学完之后，你应该能凭直觉判断："这个过滤条件应该写在 WHERE 里还是 HAVING 里？"

## 数据库故事

这节课的练习数据是一个**健身手环的每日记录**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `daily_logs` | 每个用户每一天的运动数据（步数、消耗卡路里、活跃分钟、距离公里） | 150 |

数据来自 **10 个用户**，每人记录了 **15 天**（2025-05-01 到 2025-05-15）。
用户之间运动水平差别故意做得很明显 —— 有人天天暴走，有人基本宅家 ——
这样 `HAVING avg(steps) >= 8000` 这种条件才能真正起到"过滤"作用，
查询结果不是"全员通过"，也不是"全员淘汰"。

## 先自己探索一下

正式开始前，**强烈建议你先自己动手点一点**：

- 在 DBeaver 左侧栏里展开 `daily_logs`，双击预览数据。
- 看每一列叫什么名字、是什么类型。
- 滚一滚数据，记一下大致有哪几个用户、每天的步数范围大致是多少。
- 心里先估一估："如果按用户分组求平均步数，哪几个人会超过 8000？"

带着这个预估再去看下面的查询结果，你会对 `HAVING` 的作用有更直观的体会。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛 ——
注释和代码住在一起，比单独翻教程要省事得多。
