# Lesson 11 — 聚合函数（还没到 GROUP BY）

> 不用 `GROUP BY`，单凭聚合函数本身，就能把一整张表"压"成一行总结。

## 我们要学什么

这节课我们一起来认识 SQL 里最常用的几个**聚合函数**。
它们的共同点是：**把多行数据计算成一个值**。

| 函数 | 一句话 |
|------|--------|
| `COUNT(*)` | 一共有多少行 |
| `COUNT(col)` | `col` 不为 NULL 的行数 |
| `COUNT(DISTINCT col)` | `col` 有多少个不重复的值 |
| `SUM(col)` | `col` 的总和 |
| `AVG(col)` | `col` 的平均值 |
| `MIN(col)` / `MAX(col)` | `col` 的最小 / 最大值（数字、日期、字符串都行） |

这节课**故意不讲 `GROUP BY`**——下一节课才出场。
现在你脑子里只要一个画面：**整张表 → 一行结果**。

最重要的一个隐藏知识点：**所有聚合函数都会悄悄忽略 NULL**。
这是新手最容易踩的坑，我们用第一个例子把它讲透。

## 数据库故事

这节课的数据是一份**个人银行账户的流水**，从 2025 年 1 月到 3 月。

| 表名 | 内容 | 行数 |
|------|------|------|
| `transactions` | 每一笔交易：账户、日期、分类、商户、金额、借/贷类型 | 100 |

字段里有几个值得注意的设计：

- `category` **故意留了一些 NULL**——模拟"还没来得及打标签"的交易，用来演示 `COUNT(*)` 和 `COUNT(col)` 的差别。
- `type` 只有两个值：`debit`（支出）和 `credit`（进账）。
- 商户和分类都很真实（Whole Foods、Starbucks、Netflix、房租、工资……），方便你建立"画面感"。

## 先自己探索一下

正式开始前，**强烈建议你先自己动手点一点**：

- 在 DBeaver 左侧栏里展开 `transactions`，双击表名预览数据。
- 看一眼 `category` 这一列——你会发现有几行是空的（NULL），记住这些行的存在。
- 翻一翻 `merchant` 这一列：哪些商户反复出现？哪些只出现过一次？
- 留意 `type` 列——大多数是 `debit`，但每月的工资是 `credit`。

这些"肉眼观察"会直接影响你对后面查询结果的判断。
比如你已经知道 NULL 存在了，那看到 `COUNT(*)` 和 `COUNT(category)` 数字不一样就不会惊讶了。

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
