# Lesson 09 — 计算列和 CASE 表达式

> 数据库里没有现成的"总价"列怎么办？想把订单状态按工作流顺序排怎么办？这节课教你**在 SELECT 里现场算列**。

## 我们要学什么

到目前为止，我们查询出来的列都是表里**本来就有**的列。但真实业务里，最值钱的那一列经常**不在表里**——
- "总价"通常没存，只存了单价、数量、运费、小费；
- "订单是否完成"通常没存，只存了一个 status 字符串；
- "订单金额档位"（S/M/L/XL）更是只在产品经理脑子里。

这节课我们学怎么**在查询里现场把这些列算出来**，重点是两件事：

| 构件 | 一句话 |
|------|--------|
| **算术 / 字符串拼接** | 用 `+ - * /` 和 `\|\|` 把已有的列拼成新列 |
| **`CASE WHEN ... THEN ... ELSE ... END`** | SQL 的内联 if/else——把一个值按规则映射到另一个值 |

`CASE` 是这节课的重头戏。它能做的事远不止"把 status 改成中文"——
它能给 ORDER BY 一个自定义的排序顺序，能给行打分类标签，能给行打 0/1 标记方便后续聚合。
学会 `CASE`，你就能用 SQL 表达大部分"分情况讨论"的业务逻辑。

## 数据库故事

这节课的数据是一份**外卖订单流水**。

| 表名 | 内容 | 行数 |
|------|------|------|
| `delivery_orders` | 每一条订单明细（餐厅、菜品、数量、单价、运费、小费、订单状态、下单时间） | 60 |

数据里包含了 Shake Shack、Chipotle、Domino's、Sweetgreen、Starbucks 等真实餐厅，

## 关于 SQL 注释（小知识）

你会发现每个 example 文件里都有一大堆以 `--` 开头的文字。
SQL 有两种注释写法：

```sql
-- 单行注释：从 -- 到这一行结尾的内容都被数据库忽略。

/*
 * 块注释：可以跨多行。
 * 写长一点的说明很方便。
 */
```

数据库**会直接忽略**注释，所以你随便写，**不会影响**查询结果。
我们在每个 example 文件里把"业务问题"和"为什么这么写"都用注释写在 SQL 旁边，
就是希望你以后回过头来看也能立刻想起这条 SQL 在干嘛——
注释和代码住在一起，比单独翻教程要省事得多。
