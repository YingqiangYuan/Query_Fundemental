## 5. Hostile-scan rules for Audit mode

Audit assumes a hostile reader scanning with the question "did this come from a tutorial?". Each rule category has explicit detection patterns and a severity tier.

### File-pattern flags

🔴 **HIGH RISK** — fatal-on-detection:

- `**/README-cn.md` at any depth — locale-suffix READMEs are unambiguous teaching tell.
- `**/README-<locale>.md` for any locale (`-zh`, `-ja`, `-de`, `-es`, `-fr`, etc.) — generalize the pattern.
- `README-ORIGINAL.md`, `README-OLD.md`, `README-DRAFT.md` — refactor-leftover patterns.
- `**/*-tutorial.md`, `**/*-course.md`, `**/*-lesson.md` — explicit teaching suffixes.
- `docs/learn-this-project/` directory — the mentor analysis dir.
- `docs/tutorials/` directory — the lesson-smith course archive.
- `.claude/skills/learn-this-project-absorb/`, `-elevate/`, `-quiz/`, `-interview/`, `-demo/`, `-publish/` — the 6 generated child skills. `learn-this-project-meta/` is **allowed** (per project convention).
- `.claude/skills/lesson-smith-*/` directories — content-generation skill family.

🟡 **MEDIUM RISK** — recoverable but visible:

- `__pycache__/`, `*.egg-info/`, `.pytest_cache/` — Python build/test artifacts.
- `.idea/`, `.vscode/settings.json` if it contains user-specific config — IDE leaks.
- `.venv/`, `venv/`, `env/` — committed virtualenv (Python anti-pattern).
- `.DS_Store` — macOS file system metadata.
- Any `tmp/` or `scratch/` directory with content — scratch leak.
- `CLAUDE.md`, `.cursor/`, `.aider*` — AI-tooling files. Some viewers are neutral; some are negative.

🔵 **LOW RISK** — cosmetic:

- No `LICENSE` file at root.
- No `CONTRIBUTING.md`.
- Missing entries in `.gitignore` for `__pycache__/`, `.venv/`, `.idea/`, `.DS_Store`.

### README phrase flags

🔴 **HIGH RISK**:

- "this tutorial", "this course", "in this lesson", "we'll learn"
- "as a student", "as a learner", "the mentor"
- "course material", "lesson material", "lesson plan"
- "this guide will teach you" (subtle but common)
- First-person plural learning prose ("we" + present-tense verb in a non-collaborative repo)

🟡 **MEDIUM RISK**:

- "exercises", "homework", "quiz", "test yourself" (unless the repo legitimately has exercise files)
- "mentor", "instructor", "teaching assistant"
- "syllabus"

🔵 **LOW RISK**:

- README length under 50 words — looks unfinished.
- README contains only the project tagline — looks unfinished (the current `README.md` is exactly this; publish must rewrite it).

### Commit-message phrase flags

🟡 **MEDIUM RISK** — flag commit subjects/bodies containing:

- "lesson NN", "tutorial", "course"
- "as a learner", "for the student"
- "fix typo in lesson"
- Conversational AI-assistant-style messages (`"feat:"` followed by suspiciously perfect prose; very long bodies that read as ChatGPT output)

Detect by `git log --format='%s%n%b' main..HEAD` or full-history `git log --all --format='%s'` for thorough audit.

### Git ref flags

🔴 **HIGH RISK** — detect by `git tag --list` + `git branch --all`:

- Tags named `tutorial-base`, `from-tutorial`, `original`, `v0-from-course`, `pre-publish`
- Branches named `tutorial`, `course`, `learning-*`, `from-meta-skill`, the current `01-Learn-This-Project` branch from this repo

🟡 **MEDIUM RISK**:

- Branches with personal names (`<student>-experiments`) — fine if intentional, suspicious if leftover.

### Residual directory flags

🔴 **HIGH RISK**:

- Any `.claude/skills/learn-this-project-*/` directory **other than** `learn-this-project-meta/` (which is allowed per the project's README convention).

### Hygiene flags (lower-risk but ugly)

🟡 **MEDIUM RISK** — same set covered in file-pattern flags above (`.idea/`, `__pycache__/`, `.venv/`, OS junk).

🔵 **LOW RISK**:

- `.DS_Store` in repo (macOS) or `Thumbs.db` (Windows).
- Empty directories committed via `.gitkeep` for no reason.

### Suspicious symmetry flags

🟡 **MEDIUM RISK** — heuristic, not a hard rule:

- 20+ files with identical docstring shapes (e.g. every `gen_db.py` is byte-similar across lessons). This is **intentional** in this course (the uniform template is a feature), but flag it so the publish skill can either tell the user "this looks template-generated; do you want to add a comment explaining why?" or accept it.
- Identical comment banners across many SQL files (`-- Example NN:`, `-- Business question:`, `-- Why this query:`). Same intentional pattern — flag for explicit acceptance.

The Audit report should surface these as "noticed pattern: <description>; intentional? <yes/no>; recommendation: <add a CONTRIBUTING.md or convention doc explaining the pattern>".
