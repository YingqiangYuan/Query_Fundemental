# Runbook — `learn_sql_query_basic`

> Copy-pasteable commands for installing, running, testing, and debugging the course. The absorb skill walks the user through this verbatim — so every command here must be runnable as-is.

## Prerequisites

| Tool | Version | Install hint |
| :--- | :------ | :----------- |
| `mise` | latest | `curl https://mise.run \| sh` (see [mise.jdx.dev](https://mise.jdx.dev/getting-started.html)). Mise pins everything else from `mise.toml`. |
| `python` | `3.12` | Provided by mise (`tools.python = "3.12"` in `mise.toml`). After `mise install` runs, use whatever python `mise` provides. |
| `uv` | latest | Provided by mise. |

## First-time setup

Run from the repo root (`/Users/sanhehu/Documents/GitHub/learn_sql_query_basic-project/`):

```bash
mise install                # one-time: pin Python 3.12 + uv per mise.toml
mise run venv-create        # creates .venv/ via `uv venv`
mise run inst               # installs polars + SQLAlchemy via `uv sync --all-extras`
```

After this, the virtual environment lives at `.venv/`. uv-synced commands can use either `uv run <cmd>` or activate `.venv` manually.

Verify the setup is functional:

```bash
python examples/check_examples.py
```

You should see one line per `example_*.sql` file with `OK` and a row count, then a `Summary: N ok, 0 error(s)` line.

## Running locally

This project has **no service, no server, no UI**. There is nothing to "start". The runtime is the learner's SQL editor + the SQLite files on disk.

Workflow for working a single lesson (lessons 02–23):

1. `cd examples/<NN-name>/` (e.g. `examples/12-group-by/`).
2. Open the lesson's README — read the business setup + schema.
3. Open `db.sqlite` in DBeaver (or `sqlite3 db.sqlite` in a terminal).
4. Browse the tables (DBeaver: double-click → Data tab; CLI: `.tables` then `SELECT * FROM <t> LIMIT 5;`).
5. Open `example_01.sql` in your editor. Read the `-- Business question:` and `-- Why this query:` header, then run the SQL.
6. Repeat for `example_02.sql` … `example_0N.sql` in order.

Workflow for lesson 01:

1. `cd examples/01-sharpen-your-tools/`.
2. Follow the README's 6-step DBeaver walkthrough (`README.md:53–151`).
3. Connect DBeaver to `forum.sqlite`. Run `SELECT * FROM posts LIMIT 5;` as the validation that everything works.

## Tests

There is no `tests/` directory and no `pytest` setup. The course's single test is `examples/check_examples.py`.

| Question | Answer |
| :------- | :----- |
| Where do tests live? | `examples/check_examples.py` (the single file). |
| What does it cover? | Every `example_*.sql` in every `examples/NN[-_]*/` folder is executed against the folder's `db.sqlite`. OK/ERR + row count per file. Exits 1 if any SQL errors. |
| What does it **not** cover? | (1) Does **not** verify result *correctness* — only that the SQL parses and returns *some* rows. A SQL that returns wrong rows passes. (2) Does **not** verify CSV→SQLite regeneration (does not run `gen_db.py`). (3) Does **not** test against PostgreSQL/MySQL — only the committed SQLite files. (4) Does **not** check for SQL style or anti-patterns. |
| How to run? | `python examples/check_examples.py` from the repo root. |

## Common failures and fixes

| Symptom | Likely cause | Fix |
| :------ | :----------- | :-- |
| `python examples/check_examples.py` says `db.sqlite missing` for a lesson | Someone accidentally deleted the committed DB, or git checkout went wrong | `cd examples/<NN-name>/ && python gen_db.py` |
| `gen_db.py` errors with `ModuleNotFoundError: learn_sql_query_basic` | The virtualenv isn't activated, or the package isn't installed | `mise run inst` then `source .venv/bin/activate` (or prefix with `uv run`) |
| `gen_db.py` errors on a specific CSV with a dtype message | A CSV was edited and now has mixed types in a column | Inspect the CSV — polars will tell you the column. Fix the CSV data; the loader will not coerce. |
| `check_examples.py` reports `OK` but the row count looks off | A multi-statement SQL file reports only the **last** row-returning statement's count (see `check_examples.py:72-80`) | Not a bug — open the file in DBeaver to see all statement results. |
| Lesson 01 isn't in the test output | `check_examples.py` looks for `db.sqlite`; lesson 01 has `forum.sqlite` and no `example_*.sql` files | This is by design — lesson 01 is a DBeaver setup tutorial, not SQL exercises. |
| DBeaver "no driver" on first SQLite connection | The first time you connect to SQLite, DBeaver downloads the JDBC driver | Click "Download" in the driver-settings dialog; reattempt Test Connection. |
| `mise run inst` says `uv: command not found` | mise hasn't installed its tools yet | Run `mise install` first, then `mise run inst`. |

## Where to look when something breaks

- **A SQL file errors:** read the `-- Why this query:` header in the same file — it often documents the very thing the SQL is testing (e.g. `examples/12-group-by/example_06.sql:24-30` shows a deliberately-broken query). For real errors, check the file path printed by `check_examples.py` and run that file in DBeaver to see the engine's full error message.
- **`gen_db.py` errors:** the loader prints the destination DB path on success; on failure, the polars/SQLAlchemy traceback points at the CSV column. Read the CSV with `head -5 data/NN_*.csv`.
- **The loader logic itself:** `learn_sql_query_basic/csv_to_sqlite.py` is 97 lines total. `load_csv_dir_to_sqlite` (`:60`) is the entry point; `polars_dtype_to_sqlalchemy` (`:34`) is the dtype switch.
- **A lesson seems internally inconsistent (SQL doesn't match its README):** read the README, then the SQL, then look at `git log --oneline -- examples/<NN-name>/` to see if the lesson was recently edited and one side wasn't updated.
- **The course index disagrees with the lesson folders:** `examples/README.md` is the canonical index; if a lesson folder disagrees, the folder is the source of truth (the index lags edits).
